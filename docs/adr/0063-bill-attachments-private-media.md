# 0063. Bill attachments (photo/PDF of the real receipt) — private, content-addressed media

- **Status:** Accepted
- **Date:** 2026-08-15
- **Deciders:** rifki, Claude (Opus 4.8)
- **Related:** [0048](0048-minio-object-storage-for-media.md) (MinIO object storage; content-hash keys; per-service prefixes), [0030](0030-employee-expense-claims.md) §8 (the expense-receipt upload — the template this reuses), [0034](0034-pos-shell-verticals-are-adapters.md) / bill-tabs (the bill/tagihan aggregate)

## Context
Owners want to attach the **"real receipt"** (a photo of a handwritten/printed receipt) or a supporting **document** to a bill/tagihan, and keep it in the storage layer (MinIO). The repo already has the whole media path from ADR 0048: a shared `libs/media-storage` (magic-byte validate → sha256 → put under `{service}/{company}/{domain}/{sha}.{ext}`), wired into restaurant-service, with two serve idioms — **anonymous** menu images via the gateway `/api/media/restaurant/**` proxy, and **authenticated** in-service streaming for sensitive media (expense receipts). Constraints: bills are RLS-scoped (rule 5); a receipt is **business-sensitive** (must not be publicly fetchable); phone photos are large (perf); and ADR 0048 deliberately keeps uploads **service-proxied**, not presigned.

Two forces shaped the decision. (1) **Sensitivity:** the ADR 0048 anonymous policy covered the ENTIRE `restaurant/` prefix, so a bill object there would be anonymously GET-able by anyone who knew its (unguessable) content-hash — unacceptable for a receipt. (2) **File types:** owners want photos AND PDF, but the menu/QR image paths must stay image-only.

## Decision
Add a **`bill_attachment`** child table of `bill` (restaurant-service **V40**: metadata only — `object_key`, `content_type`, `byte_size`, `sha256`, `original_filename`, Auditable + FORCE RLS), storing MANY attachments per bill (append, never replace). New sub-resource endpoints on `/api/v1/bills` (already POS_ROLES at the gateway — **no gateway change**): `POST /{id}/attachments` (multipart, ≤5 MiB), `GET /{id}/attachments` (metadata list), `GET /{id}/attachments/{aid}` (**authenticated** stream, private cache + sha256 ETag + nosniff), `DELETE /{id}/attachments/{aid}` (row only — the content-addressed object is never deleted). A bill-scoped `AttachmentContentValidator` accepts JPEG/PNG/WEBP **and PDF** (`%PDF-`); `MediaKeys.extensionFor` gains `application/pdf → pdf`. Objects live under `restaurant/{company}/bill/{sha}.{ext}` and are served **only** through the authenticated endpoint — the MinIO anonymous GET policy is **narrowed to `restaurant/*/menu/*`**, so bill objects are NOT anonymously reachable. Client-side: images are compressed before upload (`attachmentImage.ts`, ~1600 px / q0.85); PDFs upload as-is. **Out of scope:** presigned direct-to-MinIO (ADR 0048 non-goal), server-side thumbnails, servicepos/carwash tickets.

## Consequences
- **Rule code now follows:** sensitive restaurant media (bill attachments) is stored under `restaurant/*/bill/*` and served only via an authenticated, bill-scoped, RLS-enforced endpoint; only `restaurant/*/menu/*` is anonymously readable. Uploads reuse the ADR 0048 lib (validate → sha256 → put → metadata row); the payload never enters the DB.
- **Enforced by / tested:** `BillAttachmentIntegrationTest` (real Postgres + in-memory store) covers image+PDF upload, list, byte-exact authenticated stream, content-addressed dedup, the type/size guards (empty→422, oversize→413), bill/tenant scoping on **both read and delete** (an attachment reads/deletes only under its own bill; another tenant can neither see nor delete it), and that a delete removes only the row while the shared object survives. `BillAttachmentControllerTest` (`@WebMvcTest` slice) pins the HTTP contract: the 413/422 RFC-7807 `ProblemDetail` shapes and the authenticated stream's private-cache + sha256 `ETag` + `nosniff` headers. Static: no-SELECT-\* + spotless.
- **Easier:** an owner attaches the real receipt to a tab from `BillDetail`; a re-view returns 304 (private ETag) instead of re-downloading; the same photo on two bills is stored once (sha256 dedup).
- **Costs / follow-ups:** narrowing the anon MinIO policy requires **re-running `minio/init.sh`** on each environment (idempotent `mc anonymous set-json`) — until then a redeployed env keeps the old broad policy. Uploads are JVM-proxied (fine at ≤5 MiB; presigned remains the ADR 0048 escape hatch if sizes grow). No thumbnails yet — the client shows the compressed full image sized down by CSS. PDF preview opens in a new tab (no inline viewer).
